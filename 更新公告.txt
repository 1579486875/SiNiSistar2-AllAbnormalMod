----------------------------------------------------------------
　　一、安装器顺手关掉 MelonLoader 的联网检查
----------------------------------------------------------------

　　有玩家问：每次启动那个黑框里都有一行红字，写着
　　「不知道这样的主机」，是不是出问题了？

　　不是。那是 MelonLoader 每次启动都会去 api.melonloader.com
　　查一下有没有现成的调试缓存，连不上就抛异常。国内网络连这个
　　域名经常解析失败，所以每次都红。

　　而且这个游戏在官方 API 上本来就查不到（返回 Game Not Found），
　　联网这一步纯属白等。

　　我们发的包本来就内置了离线依赖，用不上它。所以现在安装器
　　会顺手把 UserData\Loader.cfg 里的

　　　　force_offline_generation = false

　　改成 true。改完就不会再连网，那行红字自然没了。

　　只在配置文件已经存在时才改 —— 还没跑过游戏的话，这个文件是
　　MelonLoader 首次启动时自己生成的，安装器不插手。

　　黑框本身不会消失（日志还在里面看得到）。想连黑框一起隐藏，
　　把同一个文件里的 hide_console 改成 true 即可，日志仍然会写到
　　MelonLoader\Latest.log。

----------------------------------------------------------------
　　一、安装器现在会检查「游戏路径里有没有中文」
----------------------------------------------------------------

　　这一版没有改 Mod 本身，只在安装环节加了一道拦路检查。

　　有位玩家反馈「装完之后按 Home 和 Delete 都打不开面板」。
　　查下来不是 Mod 的问题 —— 他的游戏装在：

　　　　D:\...\workshop\content\431960\sinisisters\游戏在这里面\SiNiSistar 2 Ver1.3.0\

　　MelonLoader 的引导层定位 UnityPlayer.dll 时用的是 ANSI 路径，
　　路径里出现中文就会失败，日志里只留一行：

　　　　[ERROR] plthook_open error: Cannot get module ...\UnityPlayer.dll: 找不到指定的模块。

　　然后 MelonLoader 直接放弃，游戏按原版方式启动 —— 所以游戏能玩，
　　但 Mod 一次都没被加载过。

　　这是 MelonLoader 自己的 bug，官方 issue #910 从 0.7.1 至今没修，
　　与本 Mod 无关。所以我们只能在安装环节提前拦住。

　　现在安装器会检查目标路径，发现非英文字符时会：

　　　　· 用红字把完整路径打出来
　　　　· 说明「装了也打不开面板」
　　　　· 告诉你该怎么做（改成英文名 / 移到纯英文路径）
　　　　· 问你要不要仍然继续（默认不继续）

　　只改文件夹名不会丢存档，也不用重新下载游戏。

----------------------------------------------------------------
　　三、顺手确认了 1.3.0 的兼容性
----------------------------------------------------------------

　　那位玩家的游戏是 v1.3.0，而这个 Mod 是对 v1.3.1 编译的。
　　我们把 1.3.0 的 GameAssembly.dll 反编译出来逐项比对过：

　　　　· 70 个异常状态，ID 一个不差（None = 0 到 WetNurse = 1664246113）
　　　　· AddAbnormal / DownAbnormal / RemoveAbnormal /
　　　　　GetAbnormalLevel / LoadAbnormalData 等接口全部一致

　　结论：v1.3.0 完全可用，不需要单独做适配。

----------------------------------------------------------------
　　一、危险状态改成「可以开，但要确认两次」
----------------------------------------------------------------

　　以前这类状态是被直接封掉的：显示红色 ×、点了没任何反应。
　　现在不封了，改成让你自己确认：

　　　· 状态名变成黄色，右边显示一个 !
　　　· 点第一次：不生效，底部提示栏先给出警告
　　　· 名字转红、右边变成两个 !!
　　　· 再点一次：这才真正开启

　　关闭不受影响，点一下就关；已经开着的状态调等级也不用再确认。

　　有风险的是这 7 个：

　　　· 剧毒 / 中毒 / 昏睡 / 触手卵
　　　　　—— 写进存档后，读档会崩溃

　　　· 肉触手束缚 / 束缚 / 手部束缚
　　　　　—— 设置后可能卡住输入，只能重启游戏

　　「读档崩溃」是怎么回事：读档时游戏要按存档逐条把状态挂回去，
　　而存档里只存了「类型 + 等级」、没有伤害栈；带持续伤害那类
　　扩展组件的状态会在这条路上空引用崩溃，把整个读档流程打断 ——
　　表现是黑屏、按键全部失灵、这份存档作废。

　　★ 所以开启之前，请先手动存一次档。

　　这些状态是怎么认出来的：Mod 会直接读游戏给每个状态挂的扩展
　　组件，一个个问过去，而不是照着一张写死的名单判断。所以它跟着
　　游戏版本走，游戏更新了也不会漏。


----------------------------------------------------------------
　　二、修了一个一直没生效的功能：按住连发
----------------------------------------------------------------

　　说明书写着 A / D 与 +/- 可以按住不放连续调等级，实际上按住
　　不放也只动一下 —— 它和 W / S 共用了同一个连发计时器，而那个
　　计时器的清零条件在只按 A/D 的时候永远成立，计时器每帧都被清零。

　　现在拆成两个独立计时器，长按真的能连续调了。


----------------------------------------------------------------
　　三、修了低分辨率下顶部的状态行点不动
----------------------------------------------------------------

　　在 720x360 这类低分辨率下，面板会切成紧凑布局，顶部留白从
　　124 像素缩到 72。但「哪里算标题栏、点上去要拖动面板」这个
　　判断里把 124 写死了 —— 于是多出来的那 52 像素被当成标题栏，
　　你想点那一行的状态，结果变成了拖整个面板。

　　现在拖动区改成读面板实际用的留白值。


----------------------------------------------------------------
　　四、修了提示里的状态名和面板对不上
----------------------------------------------------------------

　　同一个状态，面板行里显示的是游戏里的官方名字，而底部提示栏
　　却写着 Mod 内置名字表里的旧名（比如面板上叫「黑暗」的，
　　提示里写成「束缚」），看着像两回事。

　　现在两处走同一套解析。


----------------------------------------------------------------
　　五、按了没反应？那是数据还在加载
----------------------------------------------------------------

　　有玩家反馈「按 A / D 或方向键都无法调整严重程度」，分两件事：

　　· 方向键 ↑ ↓ 是**刻意不支持**的。这游戏里方向键是菜单导航键、
　　　Enter 是对话推进键，面板要是占了它们，操作面板就会误触游戏
　　　自己的界面。所以一直是用 W / S 选择、A / D 调等级。

　　· 但「按 A / D 没反应」确实是个问题：状态数据是按需加载的
　　　（滚到哪加载哪），刚打开面板时如果那一行还没加载好，按键会
　　　静默失败 —— 屏幕上一点提示都没有，看着就像功能坏了。

　　现在再遇到这种情况，底部会提示「这个状态还在加载数据，稍等一下
　　再按一次」，不用再猜是不是坏了。

　　另外还细分了一层：状态栏显示 ✗ 的那些，表示自动重试已经用尽，
　　它们不会再自己好 —— 这种情况下提示会改成「这个状态加载不出来了，
　　关掉面板再打开会重新尝试」，免得你一直干等。


----------------------------------------------------------------
　　六、修了「按 A 降不动状态等级」
----------------------------------------------------------------

　　表现：按 D 升等级一直正常，但按 A 只有「当前是 Lv1」时能把状态
　　清掉，Lv2 及以上按 A 完全不减 —— 既不降级也不移除。

　　原因：降级被错并到了「升等级」那条路里。游戏在改变等级时用的接口，
　　对**已经挂着的**状态来说是「升到指定等级」，传一个更小的值它不会
　　往下调；只有「降到 0」走的是另一个接口，所以那条路一直是通的 ——
　　正好就是「只有 Lv1 时按 A 才有效」的现象。

　　现在降级改用游戏专门提供的降级接口，一次降一级，按住 A 能连续往下跳。

　　另外加了一道结果校验：万一某个状态对降级有内部保护、降不动，
　　日志里会写明「level change did not take effect」，而不是面板显示
　　降了、实际还挂着。
